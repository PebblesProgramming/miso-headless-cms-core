# Architecture v0.1 — Afgesloten

> Dit document beschrijft de architectuur zoals die was vóór de `defineBlock` refactor.
> De patronen hieronder zijn **deprecated** en mogen niet meer gebruikt worden in nieuwe code.

## Hoe het werkte

### Twee bestanden per component

Voor elk CMS block waren twee losse plekken nodig:

**1. `cms-config.json`** — het schema (velden):
```json
"hero_section": {
  "label": "Hero Sectie",
  "fields": [
    { "name": "title", "type": "text", "label": "Titel" },
    { "name": "image", "type": "media", "label": "Afbeelding" }
  ]
}
```

**2. `cms-blocks.tsx`** — de renderer:
```tsx
registerBlockRenderer('hero_section', ({ content }) => (
  <section>
    <h1>{content.title as string}</h1>
  </section>
));
```

### Workflow per nieuw block

1. Voeg toe aan `cms-config.json`
2. Schrijf renderer in `cms-blocks.tsx`
3. `npx cms sync`
4. (Soms onnodig) handmatig component aanmaken in CMS admin — sync deed dit al

### Preview

`PreviewListener.tsx` werd per project gekopieerd (copy-paste). Bij spelende trainer via `registerBlockRenderer` + `CmsBlock`, bij vrouwenvereniging via een `renderCmsBlock` switch-functie. Zelfde gedrag, andere implementatie.

---

## Waarom niet ideaal

**Drift tussen config en renderer.** De veldnaam `"title"` in JSON en `content.title` in de renderer zijn losse strings zonder verbinding. Een typo of naamswijziging in één bestand breekt de ander stilletjes — geen TypeScript error, gewoon een lege pagina.

**Dubbel werk.** Elke nieuwe client website herdefinieerde dezelfde basis-componenten (`hero_section`, `text_area`) opnieuw. Geen hergebruik.

**Copy-paste boilerplate.** `PreviewListener`, `cms.ts`, de sync-setup — alles moest per project opnieuw worden neergezet.

**Geen type safety.** Elke renderer castete velden blind: `content.title as string`. Geen compile-time garantie dat het veld bestaat of het juiste type heeft.

**Onbekende sync-mogelijkheden.** Niet bekend was dat `npx cms sync` al `ComponentDefinition::updateOrCreate` deed — componenten werden soms handmatig aangemaakt in de CMS admin terwijl de sync dat al regelde.

## Per project — staat bij afsluiting v0.1

### `de_spelende_trainer`
- `registerBlockRenderer` patroon
- `cms-config.json` bevat: hero_section, text_area, gallery_item, locatie — maar mist `over_ons_verhaal`, `profiel_card`, en de `wie-wij-zijn` pagina
- PreviewListener via `CmsBlock` (SDK registry)

### `vrouwenverenigingdoetinchem_website`
- `renderCmsBlock` switch patroon
- Rijkere component set: info_block, team_block, activity_block, gallery_block, stats_block, quote_block
- PreviewListener via directe `renderCmsBlock` aanroep

### SDK (`@miso-software/headless-cms-core`)
- `registerBlockRenderer` + `CmsBlock` + `CmsPage` als primaire rendering API
- Geen `defineBlock`
- CLI: `cms init` + `cms sync`
